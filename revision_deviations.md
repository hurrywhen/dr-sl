# Revision deviations (2026-11-18/19)

These deviations concern the new `revision_20261118` track only. Earlier D1--D18 remain in `experiment_protocol_v1.md` and are historical.

- **D-R1 (generator bug, before evaluation).** `dataset/generate_holdout.py` initially treated entity dicts as tuples in `assemble`. Fixed before any holdout result was produced. No result was reused.
- **D-R2 (duplicate filter, before evaluation).** The initial near-duplicate threshold 0.78 rejected too many instances from the new field-list template family because the templates intentionally share structure. Threshold relaxed to 0.95 before evaluation; exact duplicates still rejected. This changes generation only, not thresholds or analysis.
- **D-R3 (online audit timeout).** The first external-audit run was stopped by a 120 s harness timeout before writing results. It was rerun with a longer timeout. No partial result from the stopped run was used.
- **D-R4 (local neural service unavailable).** The local LLM endpoint was unavailable during this revision. New end-to-end results therefore use the explicit deterministic local track. The neural local-LLM track is implemented but not rerun; no online call is labelled local.

## Round 2 (2026-11-21, `revision_20261121`, protocol v2)

- **D-R5 (stability window simplified to N=1, result-preserving).** The deterministic attack/utility functions are idempotent, so the N=3 same-artifact window had exactly zero L/U range and filtered nothing. The deterministic track now declares a single effective evaluation (`DET_N_STABLE=1`); the N=3 machinery is retained only for a future stochastic neural track. Before adopting N=1 we verified that N=1 and N=3 give identical artifacts and release decisions on all 400 holdout-1 method×instance pairs, and that the re-run is byte-identical to the archived round-1 rows (0/400 mismatches). No confirmatory result changed.
- **D-R6 (extractor gaps discovered, NOT fixed post hoc).** Per-type recall on the frozen holdouts shows the deterministic extractor does not recover monetary amounts (`amount`/`charge`: the money pattern is defined in `runtime_extractor.py` but not applied by `runtime_extract`), and `email`/`allergy` recovery is template-dependent. Under the disjoint-vocabulary holdout-2, all lexicon-dependent types collapse to recall 0. Per the freeze, the extractor was **not** modified in response to these results; they are reported as findings. Any future extractor improvement must be validated on a new holdout, not on holdout-1/2.
- **D-R7 (audit coverage counting corrected).** Round-1 labelled repeated question evaluations as "unique questions" (3888). Round-2 renames this `n_question_evaluations` and separately reports unique instance–question pairs (243), unique question texts (36), attack calls, judge calls and attacker×strategy combinations. "519 hits" is relabelled total hit evaluations, not distinct leaked values. No model output changed; only the counting/reporting.
- **D-R8 (extended online audit reuses frozen round-1 outputs).** Round-2 adds `generalization_only` and `direct_forward` to the holdout-1 subset and audits a holdout-2 subset. The four previously audited methods reuse round-1 raw outputs unchanged (marked `reused_from`); only new method/instance combinations incur new model calls.
- **D-R9 (human holdout utility scoring prepared, not collected).** A blinded holdout utility scoring packet is prepared for the two co-author raters (`human_study/holdout_utility_packet/`). Real ratings cannot be collected in this automated revision; no synthetic "human" scores are invented. The packet is published as prepared-but-not-collected and listed as future work.

## Round 3 (2026-11-21/22, `results/revision_round3/`, protocol v3)

- **D-R10 (task metadata added to frozen generators, evaluated quantities unchanged).** The holdout-1/2 generators now store an explicit `task` field per template (round-2 downstream task construction inferred the task from the last sentence, which returned nearly the full prompt for 20/80 field-list instances). Before regeneration we verified that prompts, annotations, IDs and every other field are byte-identical to the frozen files (0 differences on 80+80 instances); only the metadata field was added. No round-1/2 evaluated quantity changes.
- **D-R11 (round-2 downstream invalidated and rerun).** The round-2 downstream outputs are archived under `results/revision_20261121/downstream_invalid_round2/` and are INVALID: for 8/40 audited instances the candidate answer model also saw the full original prompt via the task string. Round-3 downstream uses the explicit task (runtime isolation assertions), caches answers by artifact SHA-256 (identical artifacts reuse one answer), submits a fixed paired seed (provider honoring not guaranteed), and uses two independent judges. One transient network failure on a candidate answer was completed via the script's resume path; no partial result was used. The metric is renamed reference-answer preservation (not absolute task correctness).
- **D-R12 (Spearman tied-rank correction).** Round-2 calibration used double-argsort ranks, which break ties arbitrarily; scores concentrate on {0, 0.5, 1}. Corrected to average tied ranks with regression tests cross-validated against an independent implementation. All calibration estimates and bootstrap CIs recomputed; the round-2 stratified summary is archived as `stratified_summary_round2.json`. Corrected values match the reviewer's independent recomputation (overall rho 0.450 [0.242, 0.634]; PRISM-random sign flip −0.071→+0.303). MAE and threshold agreement were unaffected.
- **D-R13 (fixed-extractor contrast, original frozen).** `sim/runtime_extractor_fixed.py` fixes only clear implementation defects (defined-but-unused money pattern; Unicode-\w email over-match; allergy labeled form and the 孩子/患者 name-label collision with 对X过敏), with no lexicon additions. The original extractor is unchanged (hash-verified against the round-2 freeze manifest). Confirmatory validation is on the NEW holdout-3 (natural 50/50 vocabulary mix, seed 20261122, template family #3); fixed-extractor runs on holdout-1/2 are diagnostic only, since the defects were discovered there. No extractor was tuned after seeing holdout-3 results.
- **D-R14 (coverage-gate mitigation audited, base methods unchanged).** The UNSCORABLE coverage gate (no extracted task attribute → human routing) is evaluated post-hoc on holdout-1/2 rows and as a variant on holdout-3. It is an audited mitigation with a measured release-rate cost, not a claimed fix; the frozen base methods are unchanged.
- **D-R15 (residual-report claim scoped; two-type probe).** The round-2 "report recall 0" is scoped to gold-literal residue in this experiment, all of which came from never-extracted attributes; PASS instances have no report by construction. A constructed probe injects extracted values back into frozen artifacts in two modes (verbatim; normalized-equivalent evasion variant) and runs the real loop/scrub machinery, separating report coverage of detectable-but-unfixed residue from invisible never-extracted residue.
- **D-R16 (open-ended attack added; direct_forward relabelled).** An open-ended inference attack (no gold question types) is added on the holdout-1 subset for closed_loop / generalization_only / direct_forward, graded by normalized gold-literal recovery and reported as exploratory FR_open-ended. direct_forward=1.0 is a reference under the stated protocol, not a theoretical attacker ceiling.
- **D-R17 (sampling disclosure).** Downstream answer calls submit seed 20261121; whether the provider honors it is not guaranteed. Online model snapshots remain unpinned. Both are disclosed as reproducibility limitations; raw responses, task texts, artifact hashes, model names and submitted seeds are archived for audit.
